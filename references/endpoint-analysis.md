# 接口分析与内容验收

init 编写、update 修订、audit 审查 module / flow 时读取本页。本页统一定义内容标准，实际读写遵守对应工作流；audit 对不符合标准的内容只报告问题和建议。全量 init 的范围由清单约束。

## 分析单位与覆盖范围

以可定位的 REST / RPC 方法、Consumer、Job 或业务用例为分析单位。清单登记具体处理入口，页面按实际进度列出已分析与仅导航范围；不能用一个接口的说明代表整个目录。

- `navigation-only`：只建立职责、入口、代码范围和交接导航。
- `documented`：页面声明的深入范围已核对业务规则、状态、实际调用顺序、数据操作及副作用。范围之外的入口明确保留导航；不表示整个模块或运行行为已验证。
- `known-gap`：已开始分析，但声明范围中的关键本地分支、SQL、异步消费或状态回写仍未查清。保留已确认事实，列出缺口和下一处应读的实现。

部署值、远端内部实现和外部重试协议可以保持 unknown；本地请求、交接数据和失败处理应读清楚。外部未知若影响安全重跑等判断，就保留该判断为 unverified。

## 沿实现追踪

从入口读取实际执行方法，核对调用条件、业务分支、数据读写及后续处理。顺序以代码为准；不要把权限、校验、写入和通知预设成固定顺序。

Java 阅读接口后继续定位实现、运行选择的策略和相关配置；MyBatis 阅读 Mapper XML / 注解 SQL、动态片段、关联查询和通用 Mapper 的实体表映射。通用 Mapper 无 XML 时引用实际调用及实体的表名、主键映射，不猜测表名。

同步／异步、事务和异常传播要核对实际实现方法、代理调用及启用配置；接口上没有注解不能证明同步。跨目录或跨业务模块的本地实现仍须追踪，模块归属不是源码边界。宣称异常会返回调用者时，检查异常是否发生在提交任务前、异步体内或捕获范围外。

框架或依赖库行为决定关键结论时，按项目实际版本核对可用源码或官方契约；确认参数静态类型及选中的重载，不能按方法名推测 null、集合、超时或重试行为。记录查证来源；取不到版本证据时收紧结论并保留未知。

遇到事件、MQ、异步方法、调度任务或回调，继续追踪本仓库的接收方、状态回写与失败分支。发出消息或事件只是交接，不能作为最终成功。外部服务在本仓库客户端边界停止，写清请求、响应、配置和可见副作用；不虚构远端数据库和内部实现。

对关键依赖逐项归类：已追踪、已确认不适用、或尚未查清。查找不到接收方、动态路由无法确定等情况，记录位置和影响；不能把未发现写成不存在。宣称代码无运行影响时，须核对注册、配置选择、反射及动态调用线索；仅无文本调用方时写“当前仓库未发现调用方”。无需展开无关的框架内部实现。

## 逻辑说明

先讲业务动作，再讲实现。每个步骤说清“条件、操作对象、数据变化、下一步或失败结果”；只用必要的类名、方法名和字段支撑定位。

按实际执行顺序写正常路径，有差异的分支单独说明。区分申请状态、审批状态、同步状态和业务生效时间，不把它们合并成一个“成功”。失败说明哪些写入已提交、哪些后续动作未完成、状态停在哪里，以及已确认的恢复条件。

正文保持简短，表名、字段、key、topic 等细节放在步骤关联的表格中。共用规则精确链接，读者无需自行拼接多段源码摘要才能理解逻辑。

| map | 模块索引、代码范围、交接关系和未归属入口 | 业务步骤与规则；完整文件归属在清单 |

| module | 本模块入口的条件、执行规则、实际资源、提交与失败边界 | 全局定义、其他模块内部规则 |

| working-guide | 本项目手册的阅读顺序、代码定位方法和问题反馈方式 | 插件命令说明、业务规则、当前覆盖与进度 |
| .inventory.json | 当前发现范围、文件归属、入口进度、未解决缺口与续跑位置 | 页面业务说明、验收记录 |
| .state.json | 来源指纹、比较基线、来源核对时间与实际运行观察 | 页面业务说明、场景阅读结果 |
| .reviews/ | 实际题目、源码核对、原始阅读、评分和真实重读历史 | 已绑定页面与源码证据 |
| 本次答复 / 仓库外临时 session | 本次改动、检查结果、中断原因、阶段耗时、重试与格式返工 | 长期保留的业务知识及证据 |

单模块业务从 module 阅读，跨模块业务从 flow 阅读。摘要可复述必要条件、实际表与资源、状态和失败结果，使读者在该业务页看懂主线；完整规则与资源细节在权威位置维护。精简后仍须回答核心业务问题，不能把正文改成仅有链接。

页面内部也按用途分工：入口表负责定位，正文或步骤表讲执行逻辑；排障章节按症状链接对应失败分支，不再抄写正常流程；验证章节说明方法、当前有效的验证范围与结论，详细结果在对应机器记录；缺口章节记录尚未确认内容和下一处证据。代码定位与正文证据放在关联步骤，不在文末再次堆全部路径。

## 当前内容与执行记录

init / update 在原位置更新当前说明；README 的版本、时间、覆盖和续跑摘要替换旧值，不按日期追加 init / update / audit 日志。重复执行且知识、进度和证据未变时不制造文档改动。最近核对时间只取实际核对记录，重新安装、格式清理或打开页面不算新的源码验收。

模块与流程页直接写当前可证实的规则，不写“第 N 轮已修正”“按插件版本要求补齐”“读了 N 行／派了 N 个 Agent”。已解决缺口从待确认列表移除，确认后的业务事实写入对应步骤，正文不留划掉的旧缺口、修订经过或每轮验收统计。业务自身的历史版本、适用时期、迁移和时间生效规则仍须保留，并说明证据；不能把业务历史当成生成日志删除。

清理已有流水账前逐项核对：独有业务事实放回权威业务段落并关联实际证据；真实运行观察与验收证据保留在已有状态或验收记录中。日志中的“passed”“独立复核”不直接转换成有效验收；证据无法恢复时保留无法确认项。确认有效内容已有归属后再删重复过程文字，核对引用与场景，按实际语义变化复验。不新建 changelog、修订历史或执行报告文件承接流水账，也不删除原始答案、失败历史、来源指纹和仍适用的运行条件。

执行耗时、批次编号、Agent 数、读取行数、重试次数和本轮 check 统计用于本次答复，不复制进业务正文或自由说明字段。description 只说明实际复核者／读者及隔离条件，assessment 只说明该题判定与理由。保留题的最新确认与原阅读分开记录，真实重读历史按验收契约保存，不反复拼接历史文本。

## 每个已分析入口的交付内容

先用业务语言解释谁在什么条件下做什么、何时生效、完成后看到什么，再给实现细节。至少体现以下内容；可用文字或表格，同一事实在权威位置维护，其他入口精确链接。

| 内容 | 应说明的事实 |
|---|---|
| 入口与前提 | 方法/路由或订阅入口、调用方、关键入参、身份与业务权限、允许和拒绝的状态 |
| 规则与顺序 | 条件、分支、规则作用的对象、状态前后变化、实际执行顺序及原因证据 |
| 数据库 | 所有已追踪分支涉及的实际表，包括关联查询、间接写入和异步处理；读/新增/更新/删除、关键关联字段、过滤条件、软删除、事务归属 |
| 中间件与外部系统 | 本接口实际使用的 Redis、MQ、ES、RPC/HTTP 等资源，使用步骤、用途、关联标识、配置来源、失败影响 |
| 完成与异常 | HTTP/RPC 返回表示什么，异步完成看什么状态，部分失败留下什么数据，重试或补偿入口及边界 |
| 证据与缺口 | 支撑每条关键结论的实现方法、SQL、实体、配置，未读完的分支与未验证条件 |

数据库和中间件必须对应具体业务步骤，不能只写“使用 MySQL / Redis / Kafka”。一个接口有多个分支时标明每项资源在哪个分支使用；共用清单必须能看出当前接口用到哪几项。

推荐在模块页使用以下清单，也可按资源类型拆表。正文负责解释规则与先后关系，表格保存操作细节，不逐行改写表格：

| 入口 / 步骤 / 条件 | 类型与实际资源 | 操作与业务用途 | 关键字段 / 关联标识 | 事务 / 异步 / 失败影响 | 实现、SQL或配置证据 |
|---|---|---|---|---|---|

资源信息按类型具体化：

- 数据库：数据源与逐一核对的实际表名，包含主表、明细、关系表、日志表和关联查询表；不能用“主表 + N 张子表”代替表名。标明每张表在哪个条件／步骤读写，以及主键/业务键、状态、版本、租户等影响行为的字段。无需抄录全部列或完整 DDL。
- Redis：key 构造或前缀、缓存/锁/去重用途，相关 TTL、获取与释放位置。未核对锁实现时不推断所有权、续期或并发保证。
- MQ：topic 与消费组的代码值或配置键，生产和消费位置、消息关联编号、ACK/异常路径。外部投递和重试保证未经证实则标未知。
- ES：实际索引或配置键、文档关联字段、读写与刷新可见性、查不到时的行为。
- RPC / HTTP：客户端及方法、目标服务或配置键、请求与返回的关键字段、本地超时和失败处理。异步线程池或调度器影响完成、丢任务、并发时，也要体现。

无某类依赖时，只在已检查范围内注明“未使用”；仅靠 pom 中有依赖不能证明该入口会调用。动态部署值写配置键和已知环境差异；不输出密码、令牌、连接凭据或敏感运行数据。

## 证据与来源指纹

claim 用 resource_types 声明当前结论涉及的资源，sources.roles 标明实现、持久化映射、配置、接收方或定义的证据角色；格式与机械检查见[证据与定位](schema.md#证据与定位)。

行为 claim 引用实际执行实现，不能只引用 Controller 或接口声明。数据操作 claim 同时关联调用实现与 SQL / 实体映射；中间件 claim 关联使用实现与决定行为的配置。状态和规则受枚举、策略、公共组件影响时，一并引用相关文件。

据此保存来源指纹，使实现、Mapper 或配置变化能进入后续复核候选。`source_ranges` 维护相关源码、SQL与配置归属，用于候选定位；它不能代替 claim 来源的实际阅读和指纹。

区分互斥锁、重复请求识别、状态过滤和副作用幂等。看到锁、失败状态过滤或重试入口，只能描述对应机制；宣称幂等需要核对重复和并发执行、写入约束、状态提交时机、外部重复调用及部分成功。

## 内容验收

对声明为已分析的入口，从头复述一次并逐项回到证据：

1. 谁能调用，什么输入或状态会被拒绝，拒绝前是否已产生副作用？
2. 正常和关键异常分支读写哪些表、字段与中间件资源，为什么使用它们？
3. 数据、消息和关联编号如何跨步骤传递，哪一步提交，哪一步异步？
4. 接口返回成功与业务完成如何区分，最终状态和观察位置是什么？
5. 部分失败或重复执行会发生什么，哪些补偿条件已确认，哪些尚未知？

未能回答的关键本地环节继续读实现；暂时无法查清则判定存在覆盖缺口，按工作流记录或报告。外部环境和运行验证的未知单列，不用静态阅读冒充测试通过。

缺口按影响判断，不按“字段级”“内部细节”或文件长度判断。表名、关联与过滤条件、列表空值导致删除／替换、部分导入、状态回写、锁的重复执行语义等，只要影响上述问题就阻塞关联入口；同步到清单 gaps。普通展示字段等确实不影响业务判断的细节可以保留为边界，但逐项说明已确认内容、未读内容及不影响哪些结论，不将整页缺口统一归为不阻塞。无需为完成初始化逐列抄写全部表或通读无关代码。

check 只检查已记录的结构、引用、指纹和少量缺项，不解析调用图，也不能发现所有遗漏表或副作用。语义验收由 Agent 对照实现完成；标题齐全、claims 非空、脚本退出成功都不表示“已读懂业务”。

页面内容复核后，按[阅读验收](reading-review.md)检验独立读者能否回答业务问题；其结果与运行验证分别记录。

## 收尾检查

init 全量收尾、update 核对修订影响、audit 检查已有手册时共用以下范围：

- 对照清单逐入口核对进度、说明位置、来源和场景，反查已归属但未追踪的业务实现。本地缺口同步清单，不能把仅导航归为外部未知。
- 对照资源表核对 claim 的实现、映射、配置和接收方证据；泛称、表名通配或“等等”不能替代当前入口的实际资源。
- 核对交接两端及 flow：传递的数据、条件、状态一致，链接到能找到的具体段落，关键结果留在业务页。
- 回查批次遗留的待建、待分析、pending 表述。已解决的改为准确引用，真实未完成项保留；不能只删除缺口措辞。
- 核对页面和记录是否积累生成日志、旧进度、已解决缺口或重复评分说明；按上述归属规则处置，保留业务时期与实际证据。
- 核对关联场景的失败与未完成项、快照和实际时间，完成摘要不能超出验收范围。

审查幂等、安全重推、自动补偿、失败无写入、立即生效等结论时，回到对应失败和重复执行证据。尤其核对远端已成功但本地未更新、回调改变多张表、部分数据已提交的情况。

update 修改权威页面后核对引用方、流程页、资源表和场景，按语义变化复验；audit 报告实际已审与未审范围，抽查通过仅支持被审部分。
