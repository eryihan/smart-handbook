# handbook update

维护已有手册。输入是代码变化、audit 报告或已明确的内容问题；本流程负责修改知识，不修改业务源码或执行业务操作。

无手册时报告尚未建立；清单无法读取时先报告具体问题，保留已有知识，按[续跑与目标变化](../project-inventory.md#分批续跑与目标变化)判断局部恢复或交由 init 重新发现，不在 update 中默默建立新项目手册。

## 确定候选

读取旧页面、清单和状态，确认目标版本、范围和比较条件，保留旧来源与归属。先运行一次 check，合并来源变动、action_candidates、review_attention 与输入问题，再按记录／权威页组织本次范围，不逐风险重复启动验收。

- 代码变化：运行 impact，使用 related_entries 与 review_candidates，按[清单与进度](../project-inventory.md)核对新增、删除、改名、配置分支及公共使用方；依赖不明时扩大发现范围。页面快照变化也可使旧验收失效，业务代码零 diff 不表示无需处理。
- 手册问题：核对问题位置、证据、目标版本和影响范围。审计报告是输入，不能代替重新读取实现。即使 impact 没有代码变化，也继续处理已明确的内容缺陷。

候选逐项处置：无影响、定位变化、行为变化、补充遗漏、纠正错误、合并重复、删除失效内容或扩大复核范围。缺字段先判断证据，不统一判错；先补粒度、核对实际报告或现有语义，再决定哪些题需要重新独立阅读。已加载新版后的产物处理不反复安装、清空目录或从全量 init 开始；复用标准统一见清单与进度。同一权威页的本次修订合并完成后再冻结，源码复核聚焦实际变化，未影响题按具体 diff 保留。

## 修改与验收

1. 按[接口分析与内容验收](../endpoint-analysis.md)复核候选实际实现，并在权威页面修改；删除重复内容时保留业务理解所需的条件、表与资源、生效和失败结果。
2. 同步受影响的导航、关联与归属，核对引用方、流程页、资源表及接收方。受影响入口回到待复核，原有未完成项保留；原清单为 complete 时同步退回 incomplete，避免完成记录与待复核入口冲突。
3. 按[阅读验收](../reading-review.md)先检查场景计划并独立核对源码答案，再固定页面版本，独立复验受影响场景；内部工具保存实际反馈。条件、数据、状态、生效或失败说明变化不能笼统归为文案修订；未影响题依据具体 diff 核对后保留历史答案与时间说明。
4. 按[保存复核结果](../schema.md#保存复核结果)更新实际来源、场景及时间，按[收尾检查](../endpoint-analysis.md#收尾检查)核对修改影响。单元与页面复核不手填，验收未完成不能恢复 accepted / complete。

## 工具与基线

从 Skill 安装目录调用只读工具：

```sh
python3 "<skill-directory>/scripts/handbook.py" impact --root "<project-directory>" --format json
python3 "<skill-directory>/scripts/handbook.py" check --root "<project-directory>" --format json
```

CLI、比较失败与降级见[格式契约](../schema.md)。删除或替换旧关联前先完成候选分析；局部修订保留全库旧 baseline.commit。只有基线到目标的全部变更都完成归属、处置与验收才推进，修复一个原有文档错误不能直接推进全库基线。

若原初始化未完成，update 仅修订本次范围；完整存量分析仍由 init 续跑。状态损坏时保留原记录和 Markdown，只按实际核对的来源修复。

## 交付

同步 README 的覆盖与进度摘要，注明本次目标版本和记录时间。说明输入问题与比较版本、候选处置、修改页面、实际验收和检查结果、未完成项，以及全库基线是否推进。运行验证结果保留实际条件，静态阅读不冒充运行通过。
