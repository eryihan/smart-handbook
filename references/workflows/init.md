# handbook init

默认全量梳理约定范围内的存量业务，分批完成并保存进度。只有用户明确要求快速导航或局部范围时才缩小目标；局部完成不代表全库完成。

## 确认目标与已有进度

确认仓库、branch / commit / worktree、未提交修改和执行约束。结论限于已读取版本，线上版本未确认时说明。

读取已有页面、状态、清单及关联验收。已有产物先只读 check，再按[续跑与目标变化](../project-inventory.md#分批续跑与目标变化)判断复用、续跑或重建；不能看到 complete 就直接返回。已完成产物的代码变化提示 update，质量冲突提示 audit 或按缺失记录重新初始化，不自动混合命令职责。

## Agent 建立清单

按[清单与进度](../project-inventory.md)选择适合项目的发现方法，识别文件、入口、数据资源和业务关系。结合术语与业务资料理解背景，以实现核对当前规则。

清单由 Agent 建立，业务划分与分析顺序按项目判断；具体发现、归属和续跑要求统一见上述标准。

首轮发现后先保存清单，具体入口保持 pending，尚未确认范围写入 discovery.remaining；再开始逐业务深读和编写。已有清单则先保存本轮新发现。不要等全部页面或验收题组织完才首次记录进度。

## 分批追踪与编写

按[内容归属](../endpoint-analysis.md#内容归属与摘要)使用[模板](../../assets/handbook/)创建页面。

逐入口执行[接口分析与内容验收](../endpoint-analysis.md)，按其逻辑说明、资源与证据标准编写；声明资源类型与来源角色，关联清单入口与 claim。共用实现明确使用方及差异，不用少数入口代表整模块。

每批保存页面、来源指纹、入口进度、场景记录、缺口和下一步，再处理下一批。只完成一个关键模块不能结束全量 init，纳入范围的导航入口仍需继续处理。

## 复核与阅读验收

从 Skill 安装目录运行只读结构检查：

```sh
python3 "<skill-directory>/scripts/handbook.py" check --root "<project-directory>" --format json
```

修复格式和引用错误，再按[阅读验收](../reading-review.md)逐业务完成源码复核和独立阅读。答错或定位失败时补读并修正页面，不能只调整 coverage 或补齐标题。

按[状态契约](../schema.md)保存源码预期答案、独立阅读答案、逐题判定、版本快照与实际时间，失败题修订后独立复验。入口满足条件后才 accepted，模块进度派生；运行验证单独记录。Python / Git 不可用时说明降级，不能独立验收则保留未完成。

## 收尾与交付

按[收尾检查](../endpoint-analysis.md#收尾检查)核对全量记录与内容，再核对文件、入口、指纹和初始化期间变化。使用清单完成条件及 check 的派生进度核对 README；ready_to_complete 只证明记录条件，语义仍需实际复核。

同步 README 的覆盖与进度摘要，注明本次目标版本和实际记录时间，供后续直接阅读；入口进度、场景验收和来源／运行记录分别保存在清单、`.reviews/` 和状态文件中。

只有全量内容和验收完成才报告初始化完成。否则交付已完成业务、未完成项、缺口和续跑位置，保留 full 目标。说明版本、实际检查、验收与运行验证边界，给出业务手册阅读入口。
