# handbook init

默认全量梳理约定范围内的存量业务，分批完成并保存进度。只有用户明确要求快速导航或局部范围时才缩小目标；局部完成不代表全库完成。

## 确认目标与已有进度

确认仓库、branch / commit / worktree、未提交修改和执行约束。结论限于已读取版本，线上版本未确认时说明。

读取已有页面、状态和清单。有有效清单时未完成的 init 默认续跑；仅完成导航时仍按本次声明目标继续深入。缺少清单时重新发现与初始化，明确重建时先保留知识和旧来源再核对替换。

已有 full / complete 且未要求重建时，展示已完成版本与范围；后续代码变化提示使用 update，不自动改走修订流程。

## Agent 建立清单

按[清单与进度](../project-inventory.md)选择适合项目的发现方法，识别文件、入口、数据资源和业务关系。结合术语与业务资料理解背景，以实现核对当前规则。

清单由 Agent 建立，业务划分与分析顺序按项目判断；具体发现、归属和续跑要求统一见上述标准。

## 分批追踪与编写

按[内容归属](../endpoint-analysis.md#内容归属与摘要)使用[模板](../../assets/handbook/)创建页面。

逐业务执行[接口分析与内容验收](../endpoint-analysis.md)，按其逻辑说明、资源与证据标准编写，不在本流程另设一套内容要求。

每批保存页面、来源指纹、进度、缺口和下一步，再处理下一批。只完成一个关键模块不能结束全量 init。navigation-only / known-gap 如实保留，纳入全量范围的待分析项仍需继续处理。

## 复核与阅读验收

从 Skill 安装目录运行只读结构检查：

```sh
python3 "<skill-directory>/scripts/handbook.py" check --root "<project-directory>" --format json
```

修复格式和引用错误，再按[阅读验收](../reading-review.md)逐业务完成源码复核和独立阅读。答错或定位失败时补读并修正页面，不能只调整 coverage 或补齐标题。

按[状态契约](../schema.md)保存实际复核来源与日期，运行验证单独记录。Python / Git 不可用时说明降级范围；无法独立验收则保留未完成状态。

## 收尾与交付

重新核对文件、入口、指纹和未处理项，处理初始化期间变化。按清单完成条件核对全量结果、README 摘要与各业务进度。

同步 README 的覆盖与进度摘要，注明本次目标版本和实际记录时间，供后续直接阅读；详细来源、验收与验证条件仍保存在清单和状态文件。

只有全量内容和验收完成才报告初始化完成。否则交付已完成业务、未完成项、缺口和续跑位置，保留 full 目标。说明版本、实际检查、验收与运行验证边界，给出业务手册阅读入口。
