# handbook init

默认全量梳理约定范围内的存量业务，分批完成并保存进度。只有用户明确要求快速导航或局部范围时才缩小目标；局部完成不代表全库完成。

## 确认目标与已有进度

确认仓库、branch / commit / worktree、未提交修改和执行约束。结论限于已读取版本，线上版本未确认时说明。

读取已有页面、状态、清单及关联验收。已有产物先只读 check，再按[续跑与目标变化](../project-inventory.md#分批续跑与目标变化)判断复用、续跑或重建；不能看到 complete 就直接返回。已完成产物的代码变化提示 update，质量冲突提示 audit 或按缺失记录重新初始化，不自动混合命令职责。

## Agent 建立清单

按[清单与进度](../project-inventory.md)选择适合项目的发现方法，识别文件、入口、数据资源和业务关系。结合术语与业务资料理解背景，以实现核对当前规则。

清单由 Agent 建立，业务划分与分析顺序按项目判断；具体发现、归属和续跑要求统一见上述标准。

首轮发现后先保存清单，具体入口保持 pending，尚未确认范围写入 discovery.remaining；再开始逐业务深读和编写。已有清单则先保存本轮新发现。不要等全部页面或验收题组织完才首次记录进度。

## 持续处理清单

按[内容归属](../endpoint-analysis.md#内容归属与摘要)使用[模板](../../assets/handbook/)创建页面。

以清单为工作队列，重复以下批次，直到达到完成条件或出现实际中断：

1. 选择尚未完成的业务入口，优先复用已读的公共实现；批次大小由调用关系和上下文容量决定。登记 analysing，再按[接口分析与内容验收](../endpoint-analysis.md)读完本地链路并编写业务说明、资源及 claim。共用实现写清使用方和差异。
2. 按[阅读验收](../reading-review.md)一次规划本批场景和不适用理由，先修复结构，再独立核对源码答案；正确后固定页面版本，进行独立阅读和逐题评分。失败题修正后复验，不能用改状态代替。
3. 保存本批记录；仅满足验收条件的入口登记 accepted，缺口与未完成项保留。运行 check，按派生进度同步 README，再立即选择下一批。保存进度是检查点，不是结束本次 init 的理由。

宿主支持后台独立验收时，保持一个冻结批次在验，主 Agent 可分析下一批不修改其权威页、问题、claim 或来源的业务；共享页面会冲突时只读取源码并将笔记保存在仓库外。验收者只读材料，项目文件由主 Agent 顺序写入。下一批发现会影响冻结批次时先记录关联，等该批结束再修改并复验，不能并行改同一页面。后台不可用或没有独立业务时顺序执行。

记录实际可取得的分析、源码复核、阅读与等待时间，以及格式返工和阶段重试次数；工具时间与模型／网络等待分开说明，缺计时就标未记录，不估算提升比例。异常重试与记录操作遵循阅读验收，不因局部故障停止其他可做工作。

只读检查从 Skill 安装目录运行：

```sh
python3 "<skill-directory>/scripts/handbook.py" check --root "<project-directory>" --format json
```

`inventory.next_entries` 提供剩余入口 ID，Agent 根据真实缺口选择下一批，不依赖手写计数。某入口暂时缺证据时记录 known-gap 并继续其他入口；独立验收不可用时保存 needs-review，仍继续可做的源码分析。Python / Git 不可用按格式契约降级，运行验证单独记录。

全量 init 不能因为“首批完成”“一个模块已验收”或预设批次数而正常结束。允许提前结束的情况仅为用户停止、宿主实际执行限制，或剩余工作全部依赖无法取得的证据／验收条件。记录实际原因、当前入口、剩余队列和续跑位置；不能推算时间限制、假设用户需要再次确认，或把局部缺口当成全局阻塞。上下文压缩后从检查点继续。

## 收尾与交付

按[收尾检查](../endpoint-analysis.md#收尾检查)核对全量记录与内容，再核对文件、入口、指纹和初始化期间变化。使用清单完成条件及 check 的派生进度核对 README；ready_to_complete 只证明记录条件，语义仍需实际复核。

同步 README 的覆盖与进度摘要，注明本次目标版本和实际记录时间，供后续直接阅读；入口进度、场景验收和来源／运行记录分别保存在清单、`.reviews/` 和状态文件中。

只有全量内容和验收完成才报告初始化完成。实际中断时交付中断原因、已完成业务、未完成项、缺口和续跑位置，保留 full 目标。说明版本、实际检查、验收与运行验证边界，给出业务手册阅读入口。
