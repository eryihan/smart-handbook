# handbook work

## 任务上下文

识别 understand、development、debugging 或 maintenance，确认仓库、目标代码版本、worktree 和执行范围。

从目标项目 `.smart-handbook/` 的 README、map 定位相关 module / flow，比较已记录来源指纹，读取任务相关源码、SQL、配置、构建定义和必要测试。小范围任务按相关文件核对；无需先执行全库 audit。

页面缺失时直接读代码，引用失效时重新定位，文档与代码冲突时按目标版本实现判断。当前源码不能直接代表线上版本；已引用文件未变也不能排除间接依赖变化。

## understand：理解

定位业务模块和入口，梳理核心调用、状态变化、数据及依赖，再对照代码确认。

回答应给出涉及模块、入口位置、核心流程、关键状态与数据、重要依赖、源码路径和证据缺口。历史解释注明出处与适用时期，缺少证据的内容保持未知。

## development：开发

明确修改位置、现有行为、目标行为、相关影响和验证判据。用户只要求方案时按此交付；已授权实施时完成修改和范围适当的验证，记录实际结果。

核对接口、状态、SQL、配置、事务、权限、异步、重试、幂等、恢复与模块关系是否改变。受影响的 Handbook 内容按 [update](update.md) 局部更新。

## debugging：排障

确认现象、环境、运行版本和可获得的证据，建立正常状态路径，再检查实际状态和失败分支。

保留多个候选原因，分别列出支持证据、反证和下一步检查。根因结论需要验证；缺少日志不能证明步骤未执行，Mock 结果不能证明真实外部系统行为。部署版本未确认时，限定结论范围。

记录观察、推断、验证条件和缺口。经确认且可复用的判断路径写回所属 module / flow。

## maintenance：维护

定位操作入口，区分查询、写入和外部副作用，明确前提、对象、范围、幂等性、重跑条件、完成判据及风险边界。

检查事务、异步、重复消息、下游影响和失败后的恢复条件。幂等性或影响范围未知时继续分析，暂不执行无法界定影响的操作。

按用户授权执行或提供方案。执行后核对最终状态，命令退出码仅作为执行证据之一；已有授权无需重复确认。

## 交付与更新

说明已确认事实、已完成动作、实际验证及环境限制。必要时更新相关知识和来源记录；Python、Git 或历史基线不可用时按[契约](../schema.md)降级，并记录缺口。

交付内容按任务选择：理解给出结论与源码位置；开发给出变更、影响和验证结果；排障区分已确认原因与待验证假设；维护给出执行条件、实际动作和最终状态。更新知识时列出修改页面，未实施或未验证的内容明确说明。
