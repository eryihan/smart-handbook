# 阅读验收

init 验收每条业务，update 验收受影响业务，audit 复核内容时使用本页。目标是让未参与项目的研发只凭该业务手册及其链接的知识页，说清谁在什么条件下修改哪些数据、何时生效、失败停在哪里，并定位代码。

## 源码复核

复核者读取目标实现、SQL和配置，核对入口、分支、数据与副作用。依据源码提出具体场景问题，保存预期答案与证据，不仅重复模板标题。覆盖实际存在的正常路径、权限/状态拒绝、生效边界、部分失败、重复执行与异步交接。

逐业务核对，不用代表性接口替代其他入口。共用规则可合并复核，说明使用方与差异。不存在的场景说明依据，不为凑题虚构业务。

## 独立阅读

宿主支持独立上下文时，使用未继承生成历史的阅读 Agent；可使用独立子 Agent 或新上下文，不创建用户侧聊天来代替内部验收。用户指定人工验收时遵循其选择。不能隔离上下文时记录 unavailable，不自问自答后记为独立通过。

阅读者只得到目标业务、问题和手册入口，可读其链接的知识页。不给生成过程、源码答案或补充解释；不读源代码、SQL、配置、测试、历史资料，不执行代码补答案。可以报告手册标注的代码位置，不打开代码内容。

逐题给出答案、手册依据、对应代码位置和无法确认的内容。缺少说明时回答“无法从手册确认”，不凭惯例推断。

## 判定与修复

比较阅读答案与源码答案，核对事实、条件、状态、数据、生效时间和失败位置。代码定位应指向实际实现、SQL或相关配置，不只指目录。

核心问题答错、无法回答、需要从源码补答案或定位失败，验收失败。init / update 补读并修正权威页面后，用独立上下文重做受影响场景，通过后在清单记录实际范围、日期和结果。audit 只报告问题、证据与复核结果，修复和写回交给 update。辅助问题、答案和阅读结果遵守对应工作流的写入边界。

可由不同 Agent 做源码复核和阅读，阅读者始终看不到源码答案。模型同意、结构检查或文字流畅不能代替逐题核对；阅读验收不代表运行验证。
