# 阅读验收

init 验收各入口，update 复验受影响场景，audit 检查已有记录与所审业务。目标是让未参与项目的研发凭业务手册及其链接，说清调用者、条件、数据变化、生效时间、失败位置，并找到实现。

## 源码问题与答案

复核者读取实现、SQL、实体与配置，按实际分支提出场景题，先保存预期答案与证据。问题涵盖正常路径、权限/状态拒绝、生效边界、部分失败、重复执行、异步交接六个方面。它们是检查角度，不规定题数；一题可以覆盖多个方面。不适用时记录源码支持的理由，不能用通用理由跳过实际存在的分支。

逐入口核对，共用实现可以联合验收，但场景明确关联实际入口及差异。重点检查校验前副作用、外部成功后本地失败、消息发出后状态未写、异步回调回写和重复执行。发出消息、返回成功、锁或状态过滤分别描述其含义，幂等与安全重跑需要重复副作用的证据。

问题必须来自源码，不能只根据现有手册出题。每题预期答案指出条件、资源、字段、状态及停止位置，并引用实现、SQL或配置，避免把页面现有遗漏同时复制到答案里。

## 独立阅读

宿主支持时使用未继承生成历史的独立阅读 Agent 或新上下文；用户指定人工验收时遵循其选择。不能隔离则记录 unavailable。

读者只得到目标业务、问题和 Markdown 手册入口，可以读取链接的知识页。源码预期答案、机器记录和 `.reviews/` 验收附件只给评分者。读者不读取源码、SQL、配置、测试或历史材料，不执行代码补答案。

逐题回答业务结果、手册依据、实现/SQL/配置位置和无法确认项。依据指向具体段落或资源表；代码位置指向文件内的方法、SQL或行号。缺少说明时回答无法确认，不按惯例补推。

## 记录与判定

init / update 将实际场景保存在 `.smart-handbook/.reviews/<业务ID>.json`，清单入口仅引用它。结构见[验收 schema](../assets/review-schema.json)与[模板](../assets/review-template.json)，字段格式见[状态契约](schema.md#验收记录)。audit 使用仓库外临时记录，在答复中交付，不写目标仓库。

记录包含入口 ID、问题、预期答案和来源、阅读答案、手册依据、代码位置、逐题 verdict / assessment，以及目标版本、源码/页面指纹和实际时间。reader 声明实际隔离条件；声明本身不证明隔离真实完成。

评分者逐题比对条件、数据、生效、失败结果和定位。核心问题答错、无法回答、需要读源码补答案或定位失败则 failed。任何失败或未完成题均阻塞其关联入口 accepted；“4/5 通过”、修订建议已回写和模型同意不能替代失败题复验。

修订权威页面后，以独立上下文重做受影响场景，保存新的阅读答案、判定与实际时间。共同规则变化要复验实际使用方；未受影响的题保留原记录。场景分组和题数由 Agent 根据分支决定，不能拿少数题代表未分析入口。

所有来源和页面指纹对应实际复核版本；时间从宿主时钟或工具取得，不推算批次时间。验收字段中不能登记未来时间。验收记录保留未完成项，不能批量覆盖成 passed。

## 变更后的有效性

源码或页面摘要变化使旧记录进入待复核，推进其他基线不能替代重验。Agent 根据实际差异确定场景范围；修改条件、表名、状态、生效、失败或交接说明必须独立复验。

纯排版或错字修正经 diff 核对、答案和定位仍有效时，可保留历史阅读答案与时间，在 assessment 追加具体差异、实际核对时间后更新页面摘要。定位修正需复验定位。不能笼统称“文案修改”而跳过业务问题。

源码复核、独立阅读和运行验证分别表达事实。结构校验只证明记录自洽，答案真实性、发现完整性及运行行为仍需对应证据。
