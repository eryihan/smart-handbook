## 覆盖状态与缺口

从清单与 check 的派生结果汇总已确认动作、候选、已验收、待分析、待复验和有缺口的入口；与各页面 coverage 核对。证据限制与实际失败分开说明，不把队列合并成全部重跑。明确已分析范围、未检查目录和未归属入口，不能把建页或文件归属数量当作业务覆盖。详细业务边界以模块或流程页为准。

展示 full / navigation 模式、当前初始化进度与续跑位置、适用代码版本、最近实际核对时间及核对范围。更新时替换这一份摘要，不追加按日期排列的命令执行记录、Agent 分工、验收轮次或修补经过。仅格式清理不能刷新源码验收时间。

逐入口进度在 `.inventory.json`，实际场景及阅读结果在 `.reviews/`，来源指纹与运行验证在 `.state.json`。全量完成需要所有纳入范围的入口与本地业务来源有有效验收证据；存在失败题、未分析入口或失效记录时保留未完成。清单缺失或损坏时注明初始化产物不完整。
